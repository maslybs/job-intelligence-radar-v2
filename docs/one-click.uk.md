# Встановлення на Cloudflare

**Мова / Language:** [Українська](one-click.uk.md) | [English](one-click.md)
[Головна](../README.uk.md) · [Налаштування](configuration.uk.md) · [Використання](usage.uk.md)

[![Deploy to Cloudflare](https://deploy.workers.cloudflare.com/button)](https://deploy.workers.cloudflare.com/?url=https://github.com/maslybs/job-intelligence-radar-v2)

Кнопка призначена для створення **вашого власного** Worker і D1 у вашому акаунті Cloudflare. Вона не використовує базу, Telegram чи ключі автора. Перший запуск працює з демонстраційним профілем.

## Крок 1. Підготуйте акаунти

Потрібні [GitHub](https://github.com/) і [Cloudflare](https://dash.cloudflare.com/). Для D1, Workers AI та Workflows діють квоти й умови вашого тарифу; перевірте можливі витрати. Якщо у вас уже є Cloudflare Workers, **не вибирайте назву вже наявного Worker або D1**: ця процедура не призначена для оновлення вашого production-застосунку.

## Крок 2. Розгорніть проєкт

1. Натисніть **Deploy to Cloudflare** вище.
2. Увійдіть у Cloudflare та виберіть **свій** акаунт. Якщо бачите екран вибору акаунта — це очікуваний крок.
3. Авторизуйте GitHub, якщо потрібно, і задайте назву **нового** репозиторію.
4. Використайте унікальні назви Worker і D1. Якщо майстер показує команди збірки, перевірте:

   | Поле | Значення |
   | --- | --- |
   | Build command | `npm run build` |
   | Deploy command | `npm run deploy` |
   | Entrypoint | `src/index.js` |
   | D1 binding | `DB` |
   | AI binding | `AI` |

5. Підтвердьте Deploy. Скрипт виконує `wrangler deploy` і три D1-міграції. Якщо в логах є помилка міграції, встановлення не завершилося коректно.

Назви елементів інтерфейсу Cloudflare можуть змінюватися. Шаблон не має запитувати чужі ключі або токени автора.

## Крок 3. Створіть свої секрети

Якщо Cloudflare показує налаштування з `.env.example`, задайте:

- `INBOX_PASSWORD` — унікальний довгий пароль (рекомендовано 16+ символів) для входу до Inbox.
- `ADMIN_TOKEN` — **інший** випадковий токен для захищених маршрутів `/admin/*`.

Якщо полів не було, додайте їх через **Cloudflare → Workers & Pages → ваш Worker → Settings → Variables and Secrets** з типом **Secret**. Значення не повинні потрапляти у публічний репозиторій. Токен можна згенерувати локально: `openssl rand -hex 32`.

**Не** використовуйте пароль GitHub/Cloudflare як пароль Inbox. Зміна runtime secrets не змінює ваш профіль пошуку — для цього потрібна окрема змінна часу збірки, див. крок 5.

## Крок 4. Перевірте запуск

Cloudflare видасть URL формату `https://назва-worker.піддомен.workers.dev` — використовуйте **свою фактичну адресу**.

1. Відкрийте `/health`. Відповідь з `"ok":true` та HTTP 200 означає, що HTTP Worker доступний; це **не повний тест D1**.
2. Відкрийте `/inbox` і введіть `INBOX_PASSWORD`. Без налаштованого пароля вхід недоступний.
3. Перегляньте блок «Джерела». Нові джерела спочатку можуть мати стан «ще не перевірялося».
4. Cron у шаблоні запускає пошук **щогодини**, тому не очікуйте миттєвих результатів.

Для діагностики через API є [команди ручного запуску](usage.uk.md#ручний-запуск-та-діагностика).

## Крок 5. Налаштуйте профіль без публікації CV

Шаблон містить **вигаданий профіль інженера з Канади**. Щоб налаштувати власні критерії:

1. Візьміть [повний JSON-приклад](../config/radar.config.example.json).
2. Змініть роль, реальні навички, країну, допустимі регіони, бажану оплату, джерела та критерії. Не видаляйте необхідні секції схеми v2.
3. У **Cloudflare Workers Builds** встановіть `RADAR_CONFIG_JSON` як **приватну змінну часу збірки** (build-time secret) з **повним JSON**.
4. Запустіть нову збірку. Це не те саме, що runtime Worker Secret; профіль вбудовується у Worker під час build.

Не кладіть API-токени, паролі чи приватні ключі у `RADAR_CONFIG_JSON`. Докладно: [налаштування](configuration.uk.md).

## Крок 6. Користуйтеся

У `/inbox` відкривайте вакансії, переходьте до оригіналів, зберігайте цікаві, позначайте прочитані й відхиляйте нерелевантні. Додаткові RSS/ATS-джерела додаються через форму внизу сторінки. [Інструкція з використання](usage.uk.md).

Telegram, Reddit/DOU-браузер, OneAIHUB та доступ до локального комп’ютера **за замовчуванням вимкнені**.

## Типові проблеми

| Симптом | Перевірте |
| --- | --- |
| Немає доступу до Inbox | `INBOX_PASSWORD` у Worker Secrets |
| API `/admin/*` повертає 403 | `ADMIN_TOKEN` і заголовок `Authorization: Bearer ...` |
| Помилка D1 | Binding `DB`, лог розгортання, результат міграцій |
| Немає вакансій | Час Cron, журнали Workflows, статуси джерел |
| Немає сповіщень | Telegram вимкнений у стандартному конфігу |
| Оцінювання не працює | Доступність Workers AI та квоти акаунта |
| Оцінки не відповідають вам | Змініть **повний** JSON профілю та перебудуйте Worker |

**Межі перевірки:** є локальні тести, Cloudflare Runtime smoke, Wrangler dry-run та перевірка трьох міграцій на порожній D1. Повний процес у сторонньому Cloudflare-акаунті ще не перевірено end-to-end.
