# Як користуватися Job Intelligence Radar

**Мова:** Українська · [English README](../README.md)
[Головна](../README.uk.md) · [Встановлення](one-click.uk.md) · [Налаштування](configuration.uk.md)

## 1. Відкрийте Inbox

Після [встановлення](one-click.uk.md) Cloudflare надасть адресу вашого Worker (`https://ваш-worker.ваш-піддомен.workers.dev`). Додайте до неї `/inbox`. Уведіть **власний** `INBOX_PASSWORD` із Worker Secrets.

Головна сторінка `/` переспрямовує на `/inbox`. Не передавайте пароль стороннім: він відкриває ваш список вакансій.

## 2. Розбирайте знайдені вакансії

Inbox має **п'ять вкладок**:

| Вкладка | Значення |
| --- | --- |
| **Непрочитані** | Ще не розглянуті вакансії |
| **Збережені** | Ті, які хочете опрацювати пізніше |
| **Прочитані** | Переглянуті |
| **Відхилені** | Не підходять |
| **Усі** | Усі наведені статуси |

На картці вакансії видно пріоритет (`P1` тощо), оцінку `0–100`, джерело, індикатор географії (`Geo`), тип співпраці, назву, компанію та пояснення. Натисніть **«Оригінал»**, щоб перевірити справжнє оголошення і його актуальність. **Високий бал не гарантує найму або реальної наявності вакансії.**

Кнопки **«Прочитано»**, **«Зберегти»**, **«Не підходить»** та **«Повернути»** змінюють статус у D1. У поточній реалізації на сторінці показується до **30 вакансій**, інші доступні через «Наступна сторінка». Сортування враховує пріоритет P1, бал і дату знаходження.

## 3. Додавання джерел через Inbox

Прокрутіть до блоку **«Додати джерело вакансій»**:

1. У полі **«Назва джерела»** вкажіть зрозумілу назву.
2. Оберіть тип джерела: **RSS**, **Greenhouse**, **Lever**, **Ashby**, **Himalayas API** або **Jobicy API**.
3. Заповніть **відповідне поле**:
   - RSS: повна публічна адреса HTTPS RSS/Atom у полі **URL**.
   - Greenhouse, Lever, Ashby: ідентифікатор дошки вакансій у полі **ATS slug**.
   - Himalayas, Jobicy: пошуковий запит у полі **query** (наприклад `backend`).
4. Натисніть **«Додати»**.

Джерело буд�� збережено в D1 як **додаткове**, без редагування репозиторію чи нової збірки. Ліміт — **40 додаткових джерел**. Недоступні, приватні або дубльовані джерела можуть бути відхилені. Додавання джерела **не означає миттєве сканування**: далі працює запланований розклад.

Список основних джерел формується з `jobs.sources.items` у приватному конфігу часу збірки; керуйте ним за [інструкцією налаштування](configuration.uk.md).

## 4. Перевіряйте стан джерел

Унизу Inbox відкрийте секцію **«Джерела» → «Переглянути список»**. Стани:

- **OK** — останній запит успішний; це не доказ, що прийшли нові вакансії.
- **Ще не перевірялося** — для джерела ще немає результату.
- **ПОМИЛКА** — джерело не відповіло коректно.
- **ЗАСТАРІЛО** — останній успіх надто давній для встановленого інтервалу.
- **BLOCKED 403/429** — зовнішній сайт заблокував запит або обмежив частоту.

Доступні також остання перевірка, кількість отриманих і нових записів. Якщо джерело заблоковане, не обходьте його захист: використайте дозволені RSS/API або інший ресурс.

## 5. Ручний запуск та діагностика

Радар має захищений адміністративний API. Для нього потрібний **окремий** `ADMIN_TOKEN`, не пароль Inbox.

### Перевірка HTTP

Відкрийте у браузері `https://ВАШ-WORKER.workers.dev/health` — у відповіді має бути `"ok":true`. Це перевіряє доступність HTTP, але не гарантує готовність D1 і AI.

### Перевірка статистики

Для досвідчених користувачів CLI (підставте **власну** адресу Worker):

```bash
export RADAR_URL="https://YOUR-WORKER.YOUR-SUBDOMAIN.workers.dev"
read -rs RADAR_ADMIN_TOKEN
echo
curl -fsS -H "Authorization: Bearer $RADAR_ADMIN_TOKEN" "$RADAR_URL/admin/stats"
```

Команда `read -rs` читає токен без відображення введення в терміналі. **Не вставляйте реальне значення токена в приклади або логи.** Статистика показує кількість вакансій, попередні запуски, стан джерел і витрату AI-ліміту.

### Запуск сканування вручну

```bash
curl -fsS -X POST \
  -H "Authorization: Bearer $RADAR_ADMIN_TOKEN" \
  "$RADAR_URL/admin/scan"

curl -fsS -X POST \
  -H "Authorization: Bearer $RADAR_ADMIN_TOKEN" \
  "$RADAR_URL/admin/assess"
```

`/admin/scan` запускає пошук вакансій, `/admin/assess` — оцінювання накопиченої черги. Поведінка залежить від наявних джерел, D1, Workers AI та квот Cloudflare; ці запити **не гарантують нових результатів**. Не надсилайте велику кількість повторів.

## 6. Сповіщення Telegram

Типове встановлення **нічого не надсилає** в Telegram. Для цього потрібно створити власного бота і чат, додати Cloudflare Secrets `TG_BOT_TOKEN` та `TG_CHAT_ID` і ввімкнути `notifications.telegramEnabled` у **приватній** конфігурації зі збіркою Worker. Далі можна викликати захищений `POST /admin/test-telegram`.

Без надійного налаштування не вмикайте автоматичне надсилання. Не передавайте токен бота стороннім. Пошук клієнтів і приватні браузерні джерела налаштовуються незалежно.

## 7. Типові запитання

**Нічого не знаходить після Deploy.** Зразковий Cron запускається **раз на годину**. Спочатку перевірте Workflows, статуси джерел, конфігурацію профілю та статистику через `/admin/stats`.

**Оцінки не відповідають моєму досвіду.** Стартовий профіль вигаданий. Потрібно змінити `RADAR_CONFIG_JSON` в Cloudflare Workers Builds і виконати **нову збірку**.

**Пароль є, але Inbox не відкривається.** Перевірте, що `INBOX_PASSWORD` створений як runtime **Secret** саме для цього Worker; ознайомтеся з логами та обмеженням повторних невдалих спроб.

**API відповідає 403.** Перевірте `ADMIN_TOKEN`, `Authorization: Bearer ...` та правильну адресу Worker.

**Можна отримувати вакансії без OneAIHUB?** Так. Звичайні RSS, ATS та відкриті API працюють окремо. Для Reddit/DOU через браузер потрібна додаткова авторизована інтеграція.

**Чи безкоштовно це?** Репозиторій відкритий під MIT, але ресурси Cloudflare можуть мати квоти, тарифні обмеження або вартість за використання. Контролюйте споживання у власному акаунті.
